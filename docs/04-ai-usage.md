# AI 使用记录

本说明由 Codex 根据本次对话、Git 提交和实际运行记录整理，候选人授权协助编写。代码、测试、技术文档及批量评估主要由 AI 辅助完成；个人操作与自动执行的工作分别记录如下。

## AI 辅助范围

| 环节 | 使用方式与产物 |
|---|---|
| 题目分析与规格 | 前序 AI 对话起草 `spec/` 的需求、架构、工具、数据、提示词、场景与任务清单；候选人将规格和原题交给 Codex |
| 工程实现 | Codex 按阶段完成 Python CLI、7 个工具、ReAct 循环、规则与确认校验、JSON 草稿存储、幂等处理和 Trace |
| 测试与修正 | Codex 编写并执行工具、红线、存储、主循环、CLI 与场景测试；根据真实运行发现的问题增加回归用例并修正评估器 |
| 运行验证 | Codex 执行 Mock 场景、真实模型三次评估和独立新克隆验证，保留实际输出、失败记录及复测结果 |
| 文档与交付 | Codex 整理使用说明、方案、评估和本说明、复盘，处理分阶段 Git 提交及 GitHub 交付准备 |

核心运行使用原生 Python 循环，没有引入 Agent 框架。模型接口使用 OpenAI Python SDK 的兼容协议，实际模型为 DeepSeek `deepseek-flash`；依赖版本见 [环境记录](../examples/results/environment.json)。

## 验证依据与实际修正

1. 候选人手动 [S04 Trace](../examples/live/manual-S04_slot_conflict.trace.md)：模型先把“排期待确认”混为审核需确认，保存校验返回 `RISK_STATUS_MISMATCH`；模型观察到错误后修正为 `approved`，保留 `pending` 并成功保存。最终报告时间字段存在格式差异时，代码按保存事实纠正并保留 warning。
2. 首次批量真实评估为 [30/33](../examples/results/live_baseline_summary.md)。3 次失败均来自 S09 的固定 ID 断言：模型批量完成了 M07 审核，评估器却要求它为 unknown。Codex 对照原规格修正为“所有未审核素材必须为 unknown”，新增回归测试；规格和业务循环未修改。
3. 修正后重新调用真实模型，得到 [33/33](../examples/results/live_summary.md)。离线测试为 [76/76](../examples/results/pytest.txt)，Mock 场景为 [11/11](../examples/results/mock_summary.md)。Mock 结果用于流程验证，真实决策效果以 live 记录为依据。
4. 新克隆验证发现 README 缺少创建 runtime 父目录的步骤。补齐后，独立环境的安装、测试、Mock 和 [live S04](../examples/live/fresh-clone-S04_slot_conflict.trace.md) 全部通过；首次失败和复测日志均保留。

## 使用方式与约束

给 Codex 的主要指令包括：先读完整规格、按阶段实现、每阶段运行 pytest、保持验收标准、禁止发布、保存状态采用真实工具返回、硬要求和用户确认在代码中校验、每阶段提交 Git。离线阶段结束后才接入候选人配置的真实模型。

实际工具调用与结果由程序记录；Trace 只保留简要动作依据，不记录模型内部思维过程。合成输入、预期断言和固定 Mock 脚本与真实运行证据分别存放。
